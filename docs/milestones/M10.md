# M10. Pilot onboarding and trust

This report is filled in at the milestone's wrap-up. The load test section was recorded by its task.

## Load test (2026-10-24)

`pnpm db:seed:load` builds "Load Test Estates" on the local database through the app's own code (like the demo, D43): 3 businesses (GSTINs in Maharashtra, Karnataka and Haryana), 3 buildings of 40 units, 120 tenants with one lease each, and 37 months of billing (36 past months and this one): 4,440 invoices sent and 4,284 payments with TDS. Every tenth tenant hasn't paid the last three months, and nobody has paid this month yet. Seeding took 344 seconds on a MacBook. It then times, as the owner, the same functions each screen calls, twice (the second run has warm database caches); `pnpm db:seed:load --time-only` times the organization already there.

What is timed is the server's data work for each screen, not the browser's rendering, which adds little on these pages (no screen draws more than a few hundred rows).

**Fixed:** Today was over 2 seconds on a first load. Working out what each tenant owes looks up the TDS recorded against each invoice (and, since M10, against the opening balance), and `tds_records` had no index on either column, so each of the 120 tenants scanned the table. `drizzle/0035` adds both indexes.

**Still the slowest:** Today and Unpaid and ageing (about 1.4 s) work out what is owed one tenant at a time (`openInvoiceRows`: settings, invoices, payments, credit notes and TDS per tenant). They are under the 2-second bar at 120 tenants but grow with the number of tenants; doing it in one query per kind for all tenants is the next step if a landlord has a few hundred (already in `docs/BACKLOG.md`, the `openInvoiceRows` row).
